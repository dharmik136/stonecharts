# Performance Baseline Review

## Scope

This review records the approved 0.0.0.1 benchmark baseline for the Python and Go
renderers, exercising the exact workload matrix required by
[`docs/quality/benchmark-spec.md`](../../../quality/benchmark-spec.md) and
[`docs/contracts/performance-budgets.md`](../../../contracts/performance-budgets.md).

An earlier version of this benchmark harness measured a different, older dimension
(point count 3/10/100/1000 x layout style, fixed at 2 series) that did not exercise
the approved workload profiles at all. Both `libs/python/benchmark.py` and
`libs/go/cmd/benchmark/main.go` were rewritten to implement the approved matrix; this
review reflects that rewrite.

## Commands run

- `python libs/python/benchmark.py`
- `go run ./cmd/benchmark`

## Evidence artifacts

- `libs/python/benchmark_results.json`
- `libs/go/benchmark_results.json`

Both files are machine-specific benchmark output (`.gitignore`d — raw timing and
memory figures are not portable across hardware) and are regenerated by the
commands above, not committed to the repository.

## Workloads covered

- Profiles: Small (1x12), Business (8x100), Dense (20x1,000), Stress (20x5,000) -
  exactly the shapes required by the benchmark spec and budget policy.
- Variants: line, grouped-column, stacked-column.
- Output modes: SVG and HTML.
- Deterministic seeded data (seed 42, recorded generator) for every cell.
- Input spec byte length and SHA-256 recorded alongside every result.

## Measurements recorded

- Cold (first-call) and warm render time: p50, p95, p99, min, max, standard
  deviation, and sample count over 30 measured iterations (5 warm-up iterations
  first), per the spec's stated minimum.
- Peak memory: `tracemalloc` peak (Python), `runtime.MemStats` allocation delta (Go).
- Output byte size and an approximate DOM element count (regex count of
  rect/circle/ellipse/line/polyline/polygon/path/text/g tags in the rendered
  output).
- Environment: commit hash, dirty-tree state, language version, OS, architecture,
  CPU count, seed, generator, iteration counts, and the exact command.

## Deliberately out of scope for this pass

- Runtime initialization and first keyboard/tooltip interaction latency in the
  browser profile - that is `TEST-RUNTIME-BROWSER`'s territory (a live-browser
  harness), not a server-render benchmark, and is already covered under
  `REQ-A11Y-001`/`REQ-RUNTIME-001`.
- Exotic environment fields (container/virtualization detection, power mode) that
  have no portable, reliable reading on a personal development machine.
- Artifact-size evidence for shipped packages and release materials, which belongs
  to `REQ-REL-001`, not this baseline.

These are disclosed scope choices, not silent omissions.

## Reviewed result

The benchmark run completed successfully for both language implementations across
all four approved profiles and all three variants, and persisted fresh result files.
Render time scales proportionally with workload size in both languages (sub-
millisecond at Small, ~500-800ms at Stress), consistent with real, non-fabricated
measurement. The results establish a repeatable baseline for render time, memory,
and output size comparisons; per the budget policy, they do not themselves set an
absolute release threshold.

## Result

`BENCH-RENDER-BASELINE` is approved as the baseline evidence record for 0.0.0.1,
now covering the full approved workload matrix. Release-blocking thresholds remain a
separate governed decision per `docs/contracts/performance-budgets.md`.
